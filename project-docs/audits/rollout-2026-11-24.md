## The star prompt's good moment

Every `requestReview()` call, before this run: one, in `TodayView.scheduleReviewRequestAfterPositiveMoment`, triggered by a dose marked taken, a task marked done or a bill marked paid on Today. That is a real good result, not a launch, appear or count trigger, so the rollout was already present. A skipped dose never triggers it.

The moment kept: **the tick-off that clears the day**, about 3 seconds after it, only if nothing is outstanding for anyone today (every person's `PersonDigest.isClear`: no pending dose, task, appointment, refill, bill or check-in). Why: it is the core action finished with the best outcome the app has, "everything for Mom and Dad is done today", and it never lands in front of an overdue dose in a Medical-category app opened by worried people. It is never on the recipient's phone (that root never reaches Today) and never in onboarding (Today is not mounted until a person exists).

Tightened:
- The delayed ask now re-checks that Today is still on screen (`onAppear`/`onDisappear`), as well as that nothing is presented and the app is active. Before, a tab switch or a push inside the 3 seconds put the prompt over the next screen (audit M6).
- `RemoteSwitch.ratingPrompt` is checked before the call.
- The predicate is `ReviewPrompt.isGoodMoment` so it is tested.

Unchanged gates: no ask before the 2nd cold launch, 30-day cooldown stamped when the call is made, opening the write-review page ends the passive asks, sending feedback never does, a blocked ask stays pending. Settings keeps "Rate Elderhub" deep-linking to `?action=write-review`. No enjoyment question, no pre-prompt, no button trigger. No analytics capture call exists, so `rating_asked` is not logged.
